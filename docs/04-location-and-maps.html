Location & Maps

How every place in the app becomes one tap that starts navigation from wherever the phone is standing. Built around the split card, which is the clearest example because it does the hard version — two venues, one time slot, one row.

The rule the whole pattern comes from: nobody wants a map, they want to be moving. So a location is never rendered as an address to read — it's a button that hands the phone to its own maps app with turn-by-turn already running. The address itself is decoration.

01 The split card

Saturday morning had a fork: an easy option near the house or a more ambitious one further out, same slot, pick your track. Rather than stack two rows, it renders as one event split down the middle — parallel on screen because they're parallel in life — and each half carries its own time, its own photo, and its own Directions button to its own venue.

Read the anatomy bottom-up, because that's the order that matters on a phone. The Directions pill is pinned to the bottom of each half card via margin-top: auto, so the two buttons line up horizontally even though "the courts" wraps to one line and "the trails" doesn't. Uneven text above, even buttons below. That single declaration is the difference between this looking designed and looking generated.

Above it: venue name in --muted at 12px — present, but subordinate. Title at weight 800. The clock as a centred stack, start over ↓ over end, identical to every other row in the itinerary so the eye doesn't have to relearn it. Photo at a locked aspect-ratio: 16/9 rather than a fixed pixel height, so the crop never drifts as the phone gets wider.

Everything with a location uses one of three, and the choice is made by the data, not by hand.

Directions vs. the location tag

This is the bit people skip, and it's the most useful idea in here. An event at the house doesn't need a call to action — you're standing in the building. But it still needs to say where, and on Thursday, before anyone has the address, it still needs to be tappable. So the same component renders two ways off one comparison:

function MapLink({ query, label }) {
  if (!query) return null
  const home = query === HOUSE_ADDRESS
  return (
    <a className={'map-link ' + (home ? 'map-link-home' : '')}
       href={home ? mapsUrl(HOUSE_DEST) : directionsUrl(query)}
       target="_blank" rel="noreferrer"
       onClick={e => e.stopPropagation()}>
      {home ? '🏠 The house' : `${label || 'Directions'} 📍`}
    </a>
  )
}

Gold with the pin means go. Grey without it means here. Nobody has to be told; after one screen it's obvious. And note e.stopPropagation() — these pills live inside rows that are themselves tappable, and without it a tap on Directions would also fire the row's own handler.

03 The ride stack

The house gets the full treatment, because it's the destination people need at 1am and it's the only one worth three options. Three pills over the photo, top-right, stacked.

Three pills, three surfaces — gold for maps, near-black for Uber, warm bone for Waymo. The colours do the sorting at a glance, so the stack doesn't read as a wall of identical buttons. Pure white was tried for Waymo and glared against the night photo, pulling the eye off "Take me home"; the bone is still clearly the light one without being the loud one.

Two alignment details that took longer than they should have. The pills are a fixed 100px wide with content packed left, not centred and not min-width — with three stacked, the eye reads down the left edge, and centring made each label start at a different x so the icons wandered. And emoji aren't monospaced: 📍 is narrower than 🚗 which is narrower than 🤖. Each one gets boxed at a fixed width so the text starts at the same x on all three rows:

04 The URLs

All of it is plain links. No maps SDK, no API key, no embedded map tiles, no geolocation permission prompt. The phone already has a maps app that's better than anything you'd embed — the job is just to hand off to it correctly.

// Plain map view of a place.
export function mapsUrl(query) {
  return 'https://maps.google.com/?q=' + encodeURIComponent(query)
}

// Turn-by-turn FROM the phone's current location TO a destination.
// Google's universal URL opens the app if installed, else the web.
export function directionsUrl(destination) {
  return 'https://www.google.com/maps/dir/?api=1&destination='
    + encodeURIComponent(destination)
}

// Uber deep link: opens the app signed in as the rider, pickup at their
// current location, destination pre-filled — they just pick a vehicle.
// Falls back to Uber's mobile site if the app isn't installed.
export function uberUrl(destination, latlng, nickname) {
  const p = new URLSearchParams({ action: 'setPickup', pickup: 'my_location' })
  p.set('dropoff[formatted_address]', destination)
  if (latlng) {
    p.set('dropoff[latitude]',  String(latlng.lat))
    p.set('dropoff[longitude]', String(latlng.lng))
  }
  if (nickname) p.set('dropoff[nickname]', nickname)
  return 'https://m.uber.com/ul/?' + p.toString()
}

A destination is just a string in the event data — map: 'the trailhead, Old Hickory Blvd, Madison, TN' — so adding a location to anything is one field, and a missing field renders nothing at all (if (!query) return null).

05 Waymo, and the clipboard trick

Waymo has no destination deep link. You can open the app, but you can't tell it where to go. The workaround: open the app and silently copy the destination to the clipboard on the same tap, so the rider pastes instead of types.

export default function WaymoLink({ className, children }) {
  return (
    <a className={className} href={WAYMO_URL}
       target="_blank" rel="noreferrer"
       onClick={() => copyText(HOUSE_DEST)}
       title="Opens the Waymo app. Waymo can't accept a destination from a
              link, so the house coordinates are copied to your clipboard —
              paste them into the destination box.">
      {children}
    </a>
  )
}

Three rules make this safe, and all three were learned the hard way.

It stays an <a>, never a <button>. The navigation has to happen even if the clipboard write throws — Safari only grants clipboard access inside a user gesture, and an installed PWA has its own permission quirks. The href does the real work; the copy is a side effect.

The copy promise is never awaited. writeText() returns a promise that's deliberately dropped with a .catch(() => {}), so the browser follows the href on the same tick it always would. An awaited promise here would insert a delay into a hand-off that must feel instant, and a rejected one could cancel the navigation entirely.

No state, no confirmation, no label flip. The button looks identical before the tap, during, and after you come back from the Waymo app. A "Copied ✓" state on a link that navigates away is a state nobody is present to see.

06 Coordinates, not addresses

The one genuinely non-obvious decision. 1 Sample Street geocodes to the building's frontage on the main road — which is the wrong side, about 30 m from the entrance you actually want, and at night with bags that's a real walk. The dropped pin is exact.

export const HOUSE_ADDRESS = '1 Sample Street, Asheville, NC 28801'  // the label
export const HOUSE_DEST    = '36.144963,-86.785047'                 // the pin

So the app keeps both and uses each for what it's good at: the address is what you show, the coordinates are what you send. Every destination field — Google, Uber, Waymo's paste box — accepts a bare lat,lng, so this costs nothing in reliability and saves the walk. Getting this wrong is invisible in testing and obvious at 1am.

How to get the coordinates. Drop a pin in Google Maps at the actual door, share it, and read the plus code or the lat/lng out of the link. Paste that into the constant. Do it once per venue that matters; for most venues the name is fine and only the place people arrive at repeatedly is worth the effort.

07 Checklist

#Rule
1Every location is a button, not text. One tap starts navigation.
2Gold pill + 📍 = go somewhere. Grey pill, no arrow = you're already here.
3Pin the pill to the bottom of its card with margin-top: auto so buttons align across uneven text.
4e.stopPropagation() on any link inside a tappable row.
5Plain URLs only — no maps SDK, no API key, no embedded tiles.
6Store the street address for display and the coordinates for navigation. Send the coordinates.
7Ride links stay <a> tags. Never block the navigation on a clipboard promise.
8Stacked pills: fixed width, content left-packed, each emoji boxed at a fixed width.
9Any gradient-filled button needs background-origin: border-box, or a faint darker stripe appears along the top edge.
